# Devlog

## 10.11.2026
- `artuml scaffold` — applies the impl-diff result to the code itself: creates stub files for diagram classes missing from code, splices new members into existing files, patches member signatures and class kinds, and applies renames (class file + declaration + in-file members; call sites outside the file stay agent work). Placement via per-node `dir` (project-root-relative) — seeded by `scan` from the file's actual folder, settable with `--dir` on `add`/`edit node` and in the editor (**Set directory…** context entry + **Dir** toolbar button, embedded and served editors — a 1.2.3 fix restored serve mode, which the original `embedded` gate hid). Removals of code drift are gated: one y/n prompt covering all candidates, `--yes` to skip, `askBeforeRemove:false` for silent; non-TTY shells without `--yes` get the candidates listed instead and nothing is deleted. Moves: scaffold is the only mover — a class whose `dir` drifts from its actual location is `fs.rename`d into place (sole-type files only). Stub bodies per `stubBody` config (`throw` default → `NotImplementedException`, `empty`, `todo`); node notes land as `// NOTE:` comments; namespace taken from a same-folder sibling via the parse map. Refreshes `impl-diff.json`, never touches `last-ai`/`pending`, prints the judgement leftovers (call sites, declined removals, multi-type moves) under *For the agent*.
- `artuml config [key] [value]` — read/write project config from the CLI (no args = all keys, one = value, two = set). New keys `scaffoldDir` (default scaffold folder, seeded by `scan`) and `stubBody`; `serve` exposes the same via `GET/PUT /api/config` so the editor's **Dir** button edits it live. Paths are validated project-root-relative (absolute inside the root is relativized, escaping paths rejected).
- Engine is `lib/scaffold.mjs` (language-seamed like `extract.mjs`, C# only); scan's `mergeOld` copies `dir` across rescans like note, and `scan` reseeds `node.dir` from disk rather than moving anything. Requires `artisan-uml@^1.2.3` for the directory UI (contract unchanged at 2). See the hub devlog for the `/artisan-scaffold` + `/artisan-implement` pack rewrites.
- `mark-ai` attribution bug: it diffed `diagram.json` against `last-human.json` (the last ack), so any caller that ran it while the human had unacked editor edits — `/artisan-status` did unconditionally, `/artisan-scaffold`//`artisan-implement` right after their consuming `diff` — swept the human's own changes into `pending.json` as "AI changes": the next `diff` went blind on them (`last-ai.json` was advanced too) and Reject would have reverted the human's own work. It now diffs against `last-ai.json`, so it queues exactly what the next `diff` would otherwise misreport as human changes — and nothing else. Regression test added; the agent packs for status/scaffold/implement drop the unconditional call (scan + architect keep it — intentional).

## 22.09.2026
- `artisan impl-diff` — closes the loop the regular `diff` can't: the diagram compared against the actual code (read-only, marks nothing seen). Reuses the scan parser + `diffDiagram` with a name-based id alignment step (editor/CLI-added items carry random ids; diagram-unspecified types/mods never count as mismatches; notes never diffed). Report: diagram items missing from the code, code drift not in the diagram, signature mismatches. Writes `.artisan/impl-diff.json` so the editor can badge it.
- `impl-diff.json` rides along in the embedded `__ARTISAN__` payload and `refreshEmbedded()` refreshes it on every command; `serve` gets `GET /api/impl` (parses the codebase on demand — the editor polls it every 30s, unlike the 5s pending tick).
- Rescan churn fixed: `scan` now aligns fresh ids to the existing diagram **by name** before merging (`alignIds`) — nodes, members (overload-aware) and field-backed relations keep their ids across rescans, and `map.json` keys follow. Before, a rescan swapped ids on every same-name node (renamed class, editor/CLI-added class), so the editor's disk-diff reported phantom "removed + added" pairs for a semantically unchanged diagram and humans had to "Mark seen" engine noise.

## 20.09.2026
- Removals highlight now too: `remove` records `removed` refs with a ghost snapshot of what was deleted (node, member, or cascaded relations with endpoint names) — the editor draws struck-through tombstones until you confirm. (Earlier note that removals don't highlight is obsolete.)
- Fine-grained review: `artisan ack node:Wolf:removed` accepts a single ref (same `type:id:change` key format for all types), `artisan reject [keys...]` reverts diagram changes — per-ref inverse ops (un-add, un-modify via ghost, un-remove by re-inserting the ghost), or a full restore from `last-human.json` with no keys. serve gets `POST /api/ack {keys}` and `POST /api/reject {keys}` (returns the post-revert diagram so the editor can resync without phantom diffs).
- `diff.mjs` ghosts: removals, modifications and renames recorded by `diff`/`mark-ai` now carry the same ghost snapshots as CLI removals, so reverts work for agent-made changes too, and tombstones survive reloads for both paths.
- Optimistic concurrency: `PUT /api/diagram` takes `If-Match` (revision derived from the file's mtime) and answers 409 when a stale tab tries to save over newer disk state — the editor reloads disk, disk always wins.
- `POST /api/pending {refs}`: the served editor can persist its own disk-diff detections (editor-made additions/removals) so they survive a page reload, exactly like CLI-recorded refs.
- Bug: `remove node` crashed after deleting when a cascaded relation's other endpoint was looked up by id through the name-only resolver — the removal landed but the refs never got recorded (ghosts died on reload). Endpoints are resolved before the delete now.
- `artisan reject` (no keys) no longer restores `last-human.json` wholesale — that resurrected individually accepted changes (accept a removal, hit "Reject all", and the removed class came back). "Reject all" now reverts exactly the refs still pending, per-ref, and the reverse path (reject then "Mark all seen") stays safe since it never touches the diagram.
- `serve` serves the editor from `.artisan/editor/` — a bundle rebuilt in the package dist never reaches the served tab unless that folder is refreshed (rm + `artisan scan`). The drag-follow fix "not working" was just this stale copy; sync dist → pnpm store → `.artisan/editor` after every build.
- Global npm installs get `diagram.html` now: `findEditorDist` was looking for the hoisted `artisan-uml` dep at `node_modules/node_modules/artisan-uml` — a path that never exists — so `scan` skipped the self-contained editor whenever the CLI came from `npm install -g` or npx. Added the correct sibling path (`<prefix>/lib/node_modules/artisan-uml`).
